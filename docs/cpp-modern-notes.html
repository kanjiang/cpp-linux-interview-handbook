1. & 与 &&（引用）

面试语境下通常指引用，不是按位与/逻辑与。

& 左值引用 && 右值引用
绑定 有名字、还能继续用的对象 临时对象、将亡值（可被掏空）
例子 int& r = x; Order&& o = std::move(order);
目的 别名、避免拷贝传参 移动语义、完美转发

为什么要设计 &&：C++11 之前临时大对象往往只能拷贝；右值引用允许“资源搬走”而不是深拷贝，支撑移动语义和低延迟场景。运算符语境下 & 是按位与，&& 是逻辑与（短路），与引用不是同一话题。

2. std::forward

按参数原来的值类别原样转发：该左值还是左值，该右值还是右值。主要用于转发引用 T&&。

std::move std::forward
行为 无条件转成右值 有条件保持原值类别
用途 明确要移动 中间层完美转发 
template <typename T>
void wrapper(T&& arg) {
    sink(std::forward<T>(arg));
}

若写成 sink(arg)：有名字的 arg 永远是左值，右值信息会丢。forward 依赖推导出的 T 把左/右值恢复出来。

3. noexcept

声明函数不会抛异常（或在条件下不抛）。若标了 noexcept 却抛出，会 std::terminate。

  • 给编译器/STL 优化承诺：例如 vector 扩容时，移动构造若 noexcept 可放心 move，否则可能退回 copy 以保强异常安全。
  • 可用 noexcept(expr)、is_nothrow_move_constructible 做编译期分支。
  • 交易对象移动操作常写：Order(Order&&) noexcept;

4. 模板 T&&：不是“右值引用绑了左值”

Order&&：真正的右值引用，只能接右值/将亡值。

template<typename T> void g(T&& x)：转发引用（万能引用），左右值都能接——因为传左值时 T 推成 Order&，再经引用折叠变成左值引用。

传入 推出的 T 折叠后形参
左值 o Order& Order&
右值 Order{} Order Order&&

口诀：只有正在推导的 T&&（或 auto&&）才是万能引用；写成具体类型 Order&& 就只是右值引用。

5. 引用折叠

引用再套引用时不会出现“引用的引用”，而是折叠成一种引用。

组合 结果
& + &&
& + &&&
&& + &&
&& + &&&&

口诀：有左值引用参与 → 结果是 &；两个都是右值引用 → 才是 &&。

6. 类型推导入门

类型推导 = 不写死类型，编译器根据初始化式/实参推出类型。常见：auto、模板参数推导、decltype。

  • auto x = o; 通常是值类型；要引用写 auto& / const auto& / auto&&。
  • 模板 void f(T x)：按实参推出 T 再实例化。
  • decltype(expr) 更贴近表达式的类型与引用属性。

流程：看实参 → 推出 T → 若涉及 T&& 再引用折叠 → 得到最终类型。

7. 三种形参对照（Order）

按值 void f(T x)

  • f(o) / f(Order{})：T = Order，按值初始化（拷贝或移动，或 C++17 省略）。

左值引用 void g(T& x)

  • 接左值；右值 g(Order{}) 通常不行。

转发引用 void k(T&& x)

  • k(o) → T = Order&
  • k(std::move(o)) / k(Order{}) → T = Order

8. f(Order{}) 是拷贝进 x 吗？

对 template<class T> void f(T x); f(Order{});：

  1. T = Order
  2. 用右值初始化参数 x：有移动构造则优先移动，不是“只能拷贝”
  3. C++17 起，纯右值初始化同类型对象常常直接构造到 x，拷贝/移动都可省略

9. push_back 与 emplace_back

  • push_back(x)：先有一个 T，再拷贝/移动进容器。
  • emplace_back(a,b)：把构造参数完美转发，在容器内存里原地构造。
v.push_back(Order{42});   // 语义上：先有对象，再放入
v.emplace_back(42);       // 在 vector 尾部直接 Order(42)

已有对象：push_back(std::move(o))；从原材料现场造：emplace_back(...)。注意 initializer_list 与 explicit 构造时两者行为可能不同。

10. emplace_back 里的 ...

template <class... Args>
reference emplace_back(Args&&... args) {
    ::new (ptr) T(std::forward<Args>(args)...);
}
  • class... Args：类型包（任意个类型）
  • Args&&... args：参数包（转发引用）
  • forward<Args>(args)...：包展开，变成 fwd(a), fwd(b), ...
  • ::new (ptr) T(...)：placement new，在已有地址上构造

11. 返回类型 reference 是什么

不是新关键字，是容器的类型别名，对 vector<T> 通常：

using reference = T&;

所以 reference emplace_back(...) ≈ 返回新插入元素的 T&（C++17 起 vector::emplace_back 返回引用）。

Order o2(42); = 定义 Order 对象 o2，直接初始化，调用匹配的构造函数（如 Order(int)）。

12. explicit

禁止用该构造函数（或转换函数）做隐式转换，只能显式构造/转换。

struct Order {
    explicit Order(int id);
};
// process(42);     // 错
process(Order{42}); // 对
v.emplace_back(42); // 对：直接构造，不依赖隐式转换
// v.push_back(42); // 常失败

单参数构造函数默认建议加 explicit，避免 int 莫名其妙变成 Order。

13. Lambda 表达式

匿名函数对象（闭包）。基本形：[capture](params) -> ret { body }。

捕获

  • [=] 按值 / [&] 按引用 / [x] / [&x] / [=, &x]
  • [this] / C++17 [*this]
  • 按值捕获默认在 const 的 operator() 里，改副本要 mutable

为什么 [x](){ ++x; } 错？

捕获成功了，但默认 operator() 是 const，不能改按值捕获的副本。应：

auto f = [x]() mutable { return ++x; }; // 改副本
auto g = [&x]() { return ++x; };        // 改外面的 x

坑

  • 异步回调里 [&局部变量] → 悬空
  • [this] 对象先析构 → 悬空
  • 热路径慎用大 std::function 包一层

std::function<int(int,int)> = 返回 int、两个 int 参数的可调用包装。

14. operator() 与 std::function

operator()

函数调用运算符重载：让对象写成 obj(args)。带 operator() 的类叫函数对象。Lambda 本质就是编译器生成的这种类。

std::function

可调用包装器：用统一类型存函数指针 / functor / lambda（签名匹配即可）。

  • 好处：可做成员、可进容器、可运行期替换
  • 代价：类型擦除、可能堆分配、难内联 → 热路径慎用
  • 空的 function 调用会抛 bad_function_call，先 if (f)

调用链：f(1,2) → function::operator() → 真正目标的 operator() 或函数指针。

15. mutable

  • 成员：允许在 const 成员函数里修改该字段（计数、缓存、mutex）。
  • lambda：让 operator() 非 const，从而能改按值捕获的副本。

16. 热路径 / 闭包 / 语法糖

  • 热路径：跑得最勤、延迟最敏感的代码段（如下单主链路）。
  • 闭包：可调用逻辑 + 捕获走的状态打包在一起；C++ 里常是带成员的函数对象。
  • 语法糖：不增加本质能力、只让写法更短的语法。Lambda 是写闭包的语法糖，手写带 operator() 的类也能做到类似效果。
