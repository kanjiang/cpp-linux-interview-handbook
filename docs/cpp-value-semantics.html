1. 四个函数：一个比喻讲清

假设你的对象手里攥着一张房产证（指向堆内存的指针）：

class Buffer {
    char* data_;    // ← 房产证：指向一栋"房子"（堆上的内存）
    size_t size_;
};
形象比喻
  • 拷贝构造：照着你的房子再盖一栋一模一样的，给我一张新房产证 —— 贵
  • 移动构造：你的房产证直接过户给我，你手里那张作废 —— 便宜
  • 拷贝赋值：我先把自己原来的房子拆了，再照你的样子盖一栋 —— 贵
  • 移动赋值：我先拆掉自己的房子，然后接收你过户的房产证 —— 便宜

两组区别

  • 拷贝 vs 移动：拷贝后两个对象各有一栋房子；移动后只有一栋房子，换了主人，源对象变空壳。
  • 构造 vs 赋值：构造是「我刚出生，一无所有」；赋值是「我早就存在了，手上还有旧房子要先处理掉」。

2. 签名与触发时机

class Buffer {
public:
    Buffer(const Buffer& other);                 // 拷贝构造
    Buffer& operator=(const Buffer& other);      // 拷贝赋值
    Buffer(Buffer&& other) noexcept;             // 移动构造
    Buffer& operator=(Buffer&& other) noexcept;  // 移动赋值
    ~Buffer();                                    // 析构
};
Buffer a(100);

Buffer b = a;             // 拷贝构造（b 是新对象，a 是左值）
Buffer c = std::move(a);  // 移动构造（c 是新对象，源是右值）
Buffer d(200);
d = b;                    // 拷贝赋值（d 已存在）
d = std::move(b);         // 移动赋值（d 已存在，源是右值）
d = Buffer(300);          // 移动赋值（临时量是右值）
判断口诀

左边是新对象 → 构造；左边是已有对象 → 赋值。
右边是左值 → 拷贝；右边是右值（临时量或 std::move）→ 移动。

3. std::move 到底搬了什么（答案：什么也没搬）

形象比喻

接着上面「过户」的比喻：std::move 不是搬家公司，它只是在合同上盖了个「此房可过户」的章。真正跑腿的是那个类型自己的移动构造 / 移动赋值——房产证上改名、把源对象的门牌号抹掉，都写在它们的函数体里。

标准库里 std::move 的实现就这么一行，它是个类型转换，编译出来一条指令都不产生：

template <class T>
constexpr std::remove_reference_t<T>&& move(T&& t) noexcept {
    return static_cast<std::remove_reference_t<T>&&>(t);
}

所以有人说它更该叫 rvalue_cast，move 这个名字才是一切误解的源头。下面这张图把「谁在什么时候干了什么」拆开：

容易说错的一句话

「std::move 把这个变量变成了右值」——不准确。它产生的是一个值类别为右值的表达式，变量本身纹丝不动。下一行你再写这个变量名，它照样是左值。这不是抠字眼，它正好解释了下面这个人人都踩过的坑。

void g(Buffer&& x) {
    sink(x);              // ✗ 走的是【拷贝】！x 有名字，表达式 x 是左值
    sink(std::move(x));   // ✓ 这样才是右值，走移动
}

x 的类型是右值引用，但表达式 x 是左值——凡是有名字、能取地址的都是左值。如果 std::move 改的是变量属性，这里就不必再转一次了。转发场景里把 std::forward 漏掉，移动悄悄退化成拷贝，根源也在这。

3.1 盖了章，也不一定真过户

std::move 是一句许可，不是命令。它只表达「这个对象我不打算再用了，你可以搬」，至于最后搬没搬，取决于重载决议挑中了谁：

搬完之后源对象什么状态

标准的说法是「有效但未指定」（valid but unspecified）：它仍是一个完好的对象，析构一定安全，也可以给它赋新值；但你不能假设它里面还剩什么。std::string、std::vector 被移动后通常变空，那是实现细节，不是标准保证。所以移动过的对象，要么重新赋值，要么就别再读它。

面试怎么答

一句话开场：「std::move 不移动任何东西，它是个 static_cast，只把表达式转成右值；真正的搬移发生在该类型的移动构造或移动赋值里。」然后补一句「所以它是许可不是命令，类型没有移动操作时会静默退化成拷贝」，这题基本就满分了。

4. 完整实现与三个必记细节

class Buffer {
public:
    explicit Buffer(size_t n)
        : data_(new char[n]), size_(n) {}

    ~Buffer() { delete[] data_; }

    // ① 拷贝构造：盖一栋新房子，把内容搬进去
    Buffer(const Buffer& o)
        : data_(new char[o.size_]), size_(o.size_) {
        std::memcpy(data_, o.data_, size_);
    }

    // ② 移动构造：房产证过户，源对象置空
    Buffer(Buffer&& o) noexcept
        : data_(o.data_), size_(o.size_) {
        o.data_ = nullptr;      // ★ 必须置空！否则析构时房子被拆两次
        o.size_ = 0;
    }

    // ③ 拷贝赋值：先拆自己的房子，再盖新的
    Buffer& operator=(const Buffer& o) {
        if (this == &o) return *this;    // ★ 自赋值检查
        char* tmp = new char[o.size_];   // ★ 先申请成功再删旧的（异常安全）
        std::memcpy(tmp, o.data_, o.size_);
        delete[] data_;
        data_ = tmp;
        size_ = o.size_;
        return *this;
    }

    // ④ 移动赋值：先拆自己的房子，再接收过户
    Buffer& operator=(Buffer&& o) noexcept {
        if (this == &o) return *this;
        delete[] data_;          // ★ 别忘了释放自己原有的资源
        data_ = o.data_;
        size_ = o.size_;
        o.data_ = nullptr;
        o.size_ = 0;
        return *this;
    }

private:
    char* data_;
    size_t size_;
};

细节 ①：移动之后源对象必须「有效但未指定」

不是随便扔着不管 —— 它至少要能安全析构、能被重新赋值。所以一定要把指针置 nullptr。

Buffer b = std::move(a);
// a 现在是空壳，但：
a.~Buffer();        // ✓ 必须能安全析构（delete nullptr 是合法的）
a = Buffer(50);     // ✓ 必须能重新赋值
a.size();           // ✓ 允许调用，但值是"未指定"的，不要假设还有原来的数据

细节 ②：赋值必须先处理自己的旧资源

这是赋值和构造最大的区别。忘了就是内存泄漏 —— 相当于你搬进新房，旧房子还占着地不拆。

细节 ③：拷贝赋值要「先分配后释放」

而不是「先 delete 再 new」。因为 new 可能抛异常，那样你就既没了旧数据、也没有新数据。

5. 三法则 / 五法则 / 零法则

三法则（C++98）

如果你需要自己写析构函数、拷贝构造、拷贝赋值中的任意一个，那几乎肯定三个都需要。

原因很直白：需要自定义析构 → 说明你手里管着裸资源 → 那默认的浅拷贝必然出问题（双重释放）。

五法则（C++11）

写了其中一个，就该把五个都想一遍。

零法则（Rule of Zero）—— 实际最推荐

最好的做法是：一个都不写。让成员变量自己管资源，编译器生成的五个函数全都是正确的。

class Buffer {
public:
    explicit Buffer(size_t n) : data_(n) {}
    // 五个函数一个都不用写，编译器生成的全对
private:
    std::vector<char> data_;    // ← vector 自己会拷贝、会移动、会析构
};
实践结论

工程里 95% 的类都应该遵守零法则。只有在写底层容器、包装 C API 句柄、实现 RAII 封装时，才需要五法则。

6. 最大的坑：写了析构函数，移动就悄悄没了

你声明了 后果
析构函数 移动构造/移动赋值不再自动生成 → 所有"移动"退化成拷贝
任意一个拷贝操作 移动操作不再自动生成；另一个拷贝操作仍生成（但已被标记为废弃）
任意一个移动操作 两个拷贝操作被隐式 delete
易踩坑 
class Widget {
public:
    ~Widget() { log("destroyed"); }   // ← 只是想打个日志
    std::vector<int> data_;
};

Widget a;
Widget b = std::move(a);   // ✗ 实际执行的是【拷贝构造】！vector 被完整复制

只因为多写了一个析构函数，性能就悄无声息地掉了。

解决办法：真需要时把五个显式补齐，用 = default 明确要回来。

class Widget {
public:
    ~Widget() { log("destroyed"); }

    Widget() = default;
    Widget(const Widget&) = default;
    Widget& operator=(const Widget&) = default;
    Widget(Widget&&) noexcept = default;             // ← 明确要回来
    Widget& operator=(Widget&&) noexcept = default;

    std::vector<int> data_;
};

7. noexcept：为什么移动操作必须标

noexcept 是一个承诺：这个函数绝不抛异常。违背承诺时程序不会栈展开，而是直接 std::terminate()。它的价值在于：编译器和标准库会依据这个承诺选择更快的代码路径。

核心场景：std::vector 扩容

vector 满了要扩容时，需要把老数组的元素搬到新数组。它面临一个抉择：用移动（快）还是用拷贝（慢）？

而如果用拷贝，老数组原封不动，出异常时把新数组一扔就行，vector 还是原来的样子 —— 这叫强异常安全保证（要么成功，要么完全不变）。

所以

vector 的策略是：只有当元素的移动构造是 noexcept 时才用移动，否则老老实实用拷贝。内部通过 std::move_if_noexcept 实现。

后果 
class Widget {
    std::vector<char> data_;
public:
    Widget(Widget&&);            // ✗ 忘了标 noexcept
};

std::vector<Widget> v;
v.push_back(...);                // 扩容时全程【拷贝】，性能可能差几十倍

加一个 noexcept 就能让性能翻几倍，而且完全免费。

哪些地方该标 / 不该标

应该标 原因
移动构造 / 移动赋值vector 扩容等场景的性能关键
swapcopy-and-swap 惯用法的基石
析构函数C++11 起默认就是 noexcept，不用手写
简单 getter、不分配内存的函数优化收益
不该标 原因
会分配内存的（可能抛 bad_alloc）违背承诺 → terminate
调用了可能抛异常的代码同上
接口还没稳定的noexcept 属于接口的一部分，加了不好撤

补充：= default 生成的移动操作，如果所有成员的移动都是 noexcept，编译器会自动推导为 noexcept。

8. 什么时候该禁用拷贝

class Foo {
public:
    Foo(const Foo&) = delete;
    Foo& operator=(const Foo&) = delete;
};

放在 public 区，而不是 C++98 时代的「声明为 private 且不实现」—— 因为 = delete 在编译期就报错，且错误信息清晰得多。

六种典型场景

场景 说明与例子
① 独占型资源所有权 同一份资源只能有一个主人。unique_ptr、std::thread、fstream、mutex、lock_guard 都是如此；能拷贝就会 double free
② 拷贝语义讲不通 「复制一把锁」是什么意思？新锁是锁着还是开着？等它的线程怎么办？问不出合理答案就该禁用
③ RAII 守卫类 ScopedTimer、lock_guard：生命周期严格绑定作用域，拷贝会导致收尾动作执行两次
④ 有「身份」的对象 数据库连接、会话、订单实体：唯一 id、唯一 fd，复制出来两个共用一个 fd 就错了
⑤ 拷贝代价巨大想强制显式 禁掉隐式拷贝，另提供 clone()；这样传参写错会直接编译报错，而不是悄悄拷了 1GB
⑥ 单例 全局唯一实例，拷贝本身就违背设计 
std::unique_ptr<int> a(new int(1));
std::unique_ptr<int> b = a;             // ✗ 编译错误 —— 这正是设计目的
std::unique_ptr<int> c = std::move(a);  // ✓ 转移所有权
连带效应

只要拷贝操作被声明（哪怕是 = delete），移动操作就不再自动生成。

class Foo {
public:
    Foo(const Foo&) = delete;   // 声明了拷贝操作 → 移动操作不会自动生成
};

Foo a;
Foo b = std::move(a);           // ✗ 编译错误

想要「不可拷贝、但可移动」（最常见的诉求），必须显式补上 —— 这就是 unique_ptr / std::thread 的 move-only 模式：

class Connection {
public:
    Connection(const Connection&) = delete;
    Connection& operator=(const Connection&) = delete;

    Connection(Connection&&) noexcept = default;              // ← 必须显式写
    Connection& operator=(Connection&&) noexcept = default;
};

9. 决策速查表与背诵版

你的类持有什么 该怎么做
只有 vector/string/shared_ptr 等零法则：什么都别写
独占资源（fd、句柄、unique_ptr）禁用拷贝 + = default 移动 → move-only
裸指针/裸资源，且需要深拷贝五法则：五个全写，移动标 noexcept
只想加个析构日志五个补 = default，否则移动会退化成拷贝
语义上不该被复制（锁、会话、单例）= delete 拷贝
一页背诵

四个函数：拷贝＝盖新房，移动＝过户；构造是「我刚出生」，赋值是「我得先拆掉自己的旧房」。
移动后源对象必须是「空但可安全析构」的状态。
五法则：写了一个就想全五个；零法则：用智能指针和容器，一个都别写 —— 优先零法则。
坑：写了析构函数，移动就悄悄退化成拷贝。
noexcept：移动操作不标，vector 扩容就不敢用移动，性能白丢。
禁用拷贝：独占资源、语义讲不通、有唯一身份时；且记得显式补回移动，否则连移动一起没了。
